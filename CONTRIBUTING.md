# Как устроена работа над проектом

Проект ведёт один человек, поэтому правила простые. Если вы хотите что-то предложить, они же
подскажут, как это сделать удобно.

## Ветки

- **main** это то, что можно ставить. Туда попадает только проверенное, через запрос на слияние
  (pull request) из dev.
- **dev** это ветка, в которой идёт работа. Все изменения сначала попадают сюда.

Версия указывается в заголовке коммита: «DV Cloud 0.13.4: что сделано». Один коммит это один
законченный шаг, текст коммита описывает его подробно и по-русски.

## Перед слиянием в main

1. Рабочая папка чистая, dev отправлен на GitHub.
2. Тесты проходят: `npm test` во всём репозитории, на Postgres `npm run test:db --workspace @dvcloud/server`.
3. Проверка лицензий зависимостей: `npm run licenses`.
4. Нет секретов и описаний чужой инфраструктуры: ни ключей, ни паролей, ни адресов серверов. Настройки
   живут в dvcloud.env, который в git не попадает.
5. Документация обновлена вместе с кодом: если изменилось поведение, поправлен нужный файл в docs и
   добавлена строка в CHANGELOG.md.

Слияние делается запросом из dev в main с обычным коммитом слияния, чтобы в истории оставались шаги.

## Если хотите предложить правку

Откройте задачу (issue) с описанием: что не так и что ожидали. Если хотите прислать код, сначала
напишите в задаче, чтобы мы не делали одно и то же дважды. Правка должна проходить тесты и
оставлять код и документацию в том же стиле. Нашли уязвимость: не пишите о ней в открытой задаче,
используйте закрытое сообщение, как написано в SECURITY.md.

## Лицензия вклада

Присылая код, вы соглашаетесь, что он распространяется на тех же условиях, что и проект: AGPL-3.0.
