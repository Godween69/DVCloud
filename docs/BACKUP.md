# Резервная копия DV Cloud (0.9.0)

Копия делается в админке, на вкладке «Копия», и только по кнопке. Сама по расписанию она не запускается.

## Что выбрать

На вкладке «Копия» вы сами отмечаете, что брать:

- **Фото и видео** и **База данных**: можно взять только файлы, только базу или всё. Для полного восстановления нужно и то и другое.
- **Точная копия** (папка `files`): файлы лежат так же, как в облаке. Из неё облако восстанавливается. Это основной вариант.
- **Копия по людям** (папка `people`): понятная раскладка для человека, чтобы открыть фото без облака. Для каждого человека своя папка, внутри подпапки по годам или по годам и месяцам (или без подпапок), имена как в облаке или с датой впереди (`2026-05-10_123000_IMG_1.jpg`: так файлы сортируются по времени съёмки даже в самой простой программе). Одинаковые имена получают « (2)». Можно добавить папку `albums`: для каждого альбома своя папка с его файлами. Файлы в такой копии настоящие, поэтому места она занимает столько же, сколько и точная. Можно включить обе копии сразу.
- Дополнительно для точной копии: брать ли то, что лежит в корзинах, и брать ли миниатюры и копии видео (их облако строит заново, обычно не копируют).
- Ограничение скорости для копии по сети.

Если вы позже поменяете раскладку или имена, прежние папки в копии остаются: старые файлы сами не стираются.

## Что копируется

- Папка **files** (точная копия): все фото и видео ровно так, как они лежат в облаке (`library` и `trash`). Миниатюры, превью и копии видео по умолчанию не копируются: облако строит их заново. Включить их в копию можно на той же вкладке.
- Папки **people** и **albums** (копия по людям): по желанию, см. выше.
- Папка **db**: выгрузка базы данных (люди, альбомы, группы людей, отметки, настройки). Это файл `dvcloud-ГГГГММДД-ЧЧММСС.dump`. Хранятся семь последних, старые стираются.
- Не копируются никогда: временные файлы (`tmp`, `uploads`) и ключ связи с удалённым сервером (`.backup-key`).

Удалённые вами файлы из копии сами не стираются: это страховка от случайного удаления. Если копия разрослась, её можно вручную почистить.

## Как это не мешает работе облака

- Копирование идёт в фоне с самым низким приоритетом процессора.
- Файлы в облаке записываются один раз и потом не меняются, поэтому копировать их можно, пока люди пользуются облаком.
- База выгружается одним согласованным снимком и при этом не блокируется.
- Для копии по сети можно задать ограничение скорости.
- Каждая следующая копия переносит только новое и изменённое, поэтому она быстрая.

После копирования автоматически выполняется проверка: файлы на месте назначения сверяются с облаком по размеру. Если за время копии люди успели загрузить новое, это показывается как «ещё не догнано», а не как ошибка: следующая копия заберёт их.

## Куда копировать

### Диск или папка

Подходит для USB-диска, второго диска в компьютере, сетевой папки (NAS, другой компьютер дома).

Облако видит одну папку внутри контейнера: `/backup` (переменная `DVCLOUD_BACKUP_DIR`). Нужно один раз подключить туда диск на самом сервере:

1. Подключите диск к серверу и смонтируйте его в обычную папку, например `/mnt/backup`. Для сетевой папки сначала смонтируйте её (SMB или NFS) на сервере.
2. Хозяином папки должен быть пользователь с номером 1000 (в контейнере это `node`):

        sudo chown 1000:1000 /mnt/backup

3. Добавьте серверу в `docker-compose.yml` примонтированную папку и перезапустите облако:

        services:
          server:
            volumes:
              - ./data:/data
              - /mnt/backup:/backup

4. В админке, на вкладке «Копия», выберите «Диск или папка», при желании укажите подпапку и нажмите «Проверить место».

Если диск отключён, облако не пишет «в никуда»: копия не запустится, а админка скажет, что диск не подключён.

### Другой сервер по SSH

Копия уходит на другой компьютер через SSH по ключу, пароль нигде не вводится.

1. На вкладке «Копия» выберите «Другой сервер по SSH», впишите адрес сервера, порт (обычно 22), пользователя и папку на сервере, нажмите «Выбрать этот способ».
2. После этого на странице появится **открытый ключ** облака. Это строка, начинающаяся с `ssh-ed25519`. Она не секрет.
3. Добавьте эту строку новой строкой в файл `~/.ssh/authorized_keys` пользователя на сервере назначения.
4. Нажмите «Проверить место». Если вход получился, будет написано, куда и сколько там свободно.

Закрытый ключ создаётся внутри облака (в каталоге данных, в `.backup-key`) и нигде не показывается. Первое подключение запоминает отпечаток сервера; если он потом поменяется, копирование остановится с ошибкой.

## Как восстановить

Восстановление делается на сервере и только вручную: оно перезаписывает данные, поэтому его не нажать случайно.

1. Остановите облако (сервер и админку), но базу оставьте запущенной:

        docker compose stop server admin web

2. Верните файлы. Источник: `files/` из копии, назначение: каталог данных облака (`./data`). Если копия на диске:

        rsync -a /mnt/backup/dvcloud-backup/files/ ./data/

   Если на другом сервере:

        rsync -a пользователь@сервер:/путь/files/ ./data/

3. Верните базу из самой свежей выгрузки. Пустую базу создаёт сам Postgres при первом запуске; выгрузка накатывается поверх:

        docker compose exec -T db pg_restore --clean --if-exists --no-owner -U dvcloud -d dvcloud < /mnt/backup/dvcloud-backup/db/dvcloud-ГГГГММДД-ЧЧММСС.dump

4. Проверьте права: хозяин файлов должен быть пользователь 1000.

        sudo chown -R 1000:1000 ./data

5. Запустите облако. Миниатюры, превью и копии видео построятся заново сами.

Проверить, что выгрузка читается, можно в любой момент, не восстанавливая её:

    pg_restore --list dvcloud-ГГГГММДД-ЧЧММСС.dump

## Устройство

- `apps/server/src/files/backup.service.ts`: настройки (в таблице `settings`, ключи `backup` и `backup_last`), проверка места, запуск и ход.
- Внутренние пути `/internal/backup`: состояние, настройки, проверка, запуск. Админка вызывает их, сама ничего не копирует.
- В образ сервера добавлены `rsync`, `openssh-client` и `postgresql17-client` (клиент базы не должен быть старше самой базы).
- Адрес сервера, пользователь и путь проверяются жёстко (латиница, цифры и несколько знаков), чтобы из формы нельзя было подсунуть ключи команды.
- Журнал действий админа получает записи о смене настроек копии и о запуске. Пароли и ключи в журнал не попадают.
