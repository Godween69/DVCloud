# Похожие фото: дубликаты и серии

Раздел «Похожие» помогает освободить место: находит одинаковые по сути снимки и предлагает убрать лишние.
Ничего не удаляется само: отмеченные файлы уходят в корзину, откуда их можно вернуть.

## Два вида поиска

**Дубликаты** это один и тот же снимок в разном качестве: например, оригинал и копия, пришедшая из мессенджера
(она меньше по размеру и сильнее пережата). Оставляется вариант с большим разрешением, потом с большим размером
файла, потом резче. Остальные отмечаются для удаления.

**Серии** это кадры одного момента, снятые подряд. Берутся снимки, между соседними из которых не больше двух минут,
и среди них группируются похожие по цвету и составу (группа от трёх кадров). Лучшими считаются самые резкие
с учётом разрешения; оставляется примерно каждый десятый кадр, но не меньше одного и не больше трёх.

## Как это работает

Для каждого фото один раз считается маленький отпечаток и хранится в таблице file_fingerprints:

- dhash: 64 бита, «какой пиксель ярче соседнего» на картинке 9x8. Пережатие и уменьшение его почти не меняют.
- tiny: уменьшенная цветная копия 8x8 (192 байта). Сравнивается средняя разность цветов с поправкой на яркость.
- width, height: размеры после поворота по EXIF. Дубликатами считаются только снимки с одинаковыми пропорциями.
- sharpness: резкость (дисперсия лапласиана). Нужна, чтобы выбрать лучший кадр серии.
- clip: место под вектор CLIP (смысловое сходство). Пока пусто, заполнится, когда подключим модель.

Отпечатки считаются в фоне: сразу после загрузки и пачками по 20 файлов раз в 20 секунд для старых фото.
Оригинал открывается один раз и уменьшается до 256 пикселей, остальное считается по маленькой копии.
Файлы, которые не удалось разобрать (видео, неподдерживаемые форматы), просто остаются без отпечатка.

Дубликаты ищутся без перебора всех пар: 64 бита делятся на 8 байт, и при различии не более 5 бит хотя бы три
байта совпадают целиком, поэтому кандидаты находятся по совпавшему байту.

## Интерфейс запросов

Только чтение (удаление идёт обычным DELETE /api/files/:id, то есть в корзину):

- GET /api/similar/duplicates
- GET /api/similar/series

Ответ: groups (группы, лучший снимок первым, у каждого файла поле suggestRemove), images (сколько фото в библиотеке)
и ready (для скольких уже посчитан отпечаток; пока ready меньше images, результат неполный).
Пути файлов на диске наружу не отдаются. Чужие файлы не видны: поиск идёт только по файлам человека из сессии.

## Пороги и ограничения

Пороги заданы в apps/server/src/files/similar.ts (DEFAULT_DUP, DEFAULT_SERIES). Они проверены на искусственных
картинках и на настоящей базе, но подбирались не по реальной семейной библиотеке: после первого прогона на настоящих
фото их, возможно, придётся подправить.

Не находится: обрезанные или сильно отредактированные копии, видео, серии без даты съёмки (дата берётся из времени
изменения файла, которое присылает браузер). Смысловое сходство (CLIP) пока не подключено.
