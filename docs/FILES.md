# Файлы: хранение и API

Этап 1 из docs/DESIGN.md: загрузка, лента, скачивание, корзина, квота. Работает на публичном порту сервера (`/api`), вход по куке `dvcloud_sid`. Владелец всегда берётся из сессии, а не из запроса.

## Где что лежит

Всё внутри каталога данных `DVCLOUD_DATA_DIR` (в разработке `./data`, потом том на диске):

    library/<логин>/<год>/<месяц>/<файл>   оригиналы (год и месяц по дате снимка, UTC; логин того, кто загрузил первым)
    thumbs/                                миниатюры
    uploads/<id>                           недокачанные загрузки по частям; брошенные чистятся через трое суток
    tmp/                                   приём загрузки; чистится при старте сервера

Оригиналы обычные файлы: если сервер сломается, их можно открыть без него. База только индекс. Важно: `tmp`, `uploads` и `library` должны быть на одной файловой системе, иначе атомарное перемещение не сработает.

## Одна копия на всё облако

Файл на диске описывает таблица `blobs`: одно содержимое (SHA-256) это одна строка и один физический файл, сколько бы людей и альбомов на него ни ссылалось. Запись человека в `files` это «моя ссылка» на такой файл: своё имя, своя дата снимка, своё скрытие, свой учёт в квоте. Поэтому та же фотография у двух людей занимает на диске место один раз, а в квоте каждого считается полностью.

- Загрузка файла, который уже есть в облаке (у кого угодно), не кладёт второй копии на диск: создаётся только ссылка.
- «Скрыть» не двигает файл: у записи ставится метка, место в квоте остаётся занятым. Раньше файл переезжал в `trash/`, теперь каталога корзины на диске нет.
- «Убрать насовсем» стирает только ссылку человека. Файл на диске остаётся, пока на него ссылается хоть кто-то. Если не осталось никого, он считается «файлом без владельца» и физически стирается только администратором (admin → Хранилище).
- Лишние физические копии, которые остались от прежней версии (одно содержимое лежало на диске несколько раз), миграция 0006 не удаляет, а записывает в `blob_extra_paths`. Администратор проверяет их по хешу и стирает кнопкой «Удалить лишние копии».

## Запросы

Все запросы с кукой входа. Ошибки приходят как JSON с полем `message`.

- `POST /api/files?name=IMG_1.jpg` тело запроса это сам файл, `Content-Type: application/octet-stream`. Необязательный заголовок `X-File-Modified` (ISO-дата или миллисекунды) задаёт дату снимка. Ответ 201 с описанием файла, либо 200 и `duplicate: true`, если такой файл (по SHA-256) уже есть.
- `GET /api/files?limit=100&before=<курсор>` лента, свежие сверху; `next` в ответе это курсор следующей страницы. С `trashed=1` показывает корзину.
- `GET /api/files/usage` занято, квота, число файлов.
- `POST /api/files/claim` тело `{"items":[{"sha256":"…","name":"IMG_1.jpg","modified":"…"}]}` (до 200 файлов). Заявка по хешу: если такой файл уже есть в облаке, запись создаётся сразу, по сети ничего не передаётся. Для каждого файла ответ `state`: `linked` (ссылка создана), `restored` (скрытый файл возвращён), `mine` (уже есть в вашей библиотеке), `unknown` (такого в облаке нет, нужно загрузить), `quota` (не помещается в квоту), `bad` (хеш или имя неверны).
- `POST /api/files/estimate` тело `{"bytes":N}`: сколько занято, сколько свободно и поместится ли N байт.
- `POST /api/files/quota-request` тело `{"needBytes":N,"note":"…"}`: просьба администратору добавить место.
- `POST /api/files/bulk` тело `{"action":"hide|restore|remove","ids":[…]}` (до 2000): скрыть, вернуть, убрать насовсем у себя (`remove` только для скрытых).
- `DELETE /api/files/trash` убрать насовсем всё скрытое.
- `GET /api/files/<id>` отдаёт оригинал; поддерживает Range (докачка, перемотка видео). С `?download=1` как вложение.
- `GET /api/files/<id>/thumb` миниатюра; есть и у скрытых файлов, чтобы раздел «Скрытые» показывал картинки.
- `DELETE /api/files/<id>` скрыть (раздел «Скрытые», в коде по-прежнему trashed).
- `POST /api/files/<id>/restore` вернуть из скрытых (тело `{}` как JSON).
- `DELETE /api/files/<id>?permanent=1` убрать насовсем, только из скрытых.

## Загрузка по частям с докачкой

Для больших файлов (сайт делает так от 32 МБ). Нужна, чтобы обрыв связи не начинал загрузку заново.

- `POST /api/uploads` тело `{"name":"VID.mp4","size":123,"modified":"…"}`. Создаёт сессию или находит ту же самую (имя, размер, дата), поэтому загрузка продолжается и после перезагрузки страницы. Ответ: `id`, `offset` (сколько сервер уже принял), `size`, `chunk` (рекомендуемый размер куска, 8 МБ).
- `PATCH /api/uploads/<id>` тело это сам кусок, `Content-Type: application/octet-stream`, заголовок `Upload-Offset` с текущим смещением. Кусок до 64 МБ. Если смещение не совпало с принятым, ответ 409 с настоящим значением `offset`. Когда набралась полная длина, SHA-256 считается один раз, файл становится обычной записью и в ответе приходит `done: true` и `file`.
- `GET /api/uploads/<id>` сколько принято (клиент спрашивает после обрыва).
- `DELETE /api/uploads/<id>` отмена.

Принятое лежит в `uploads/<id>` и дописывается в конец, поэтому принято ровно столько байт, сколько лежит на диске. У человека не больше 50 незавершённых загрузок. Квота и размер проверяются при создании сессии.

## Правила

- Принимаются только фото и видео: jpg, jpeg, png, gif, webp, heic, heif, avif, tif, tiff, bmp, mp4, m4v, mov, avi, mkv, webm, 3gp. SVG и всё, что может нести скрипты, не принимается.
- Имя очищается: берётся последняя часть пути, убираются управляющие символы и `: * ? " < > |`, длина ограничивается. Путь на диске строится сервером, имя от клиента в нём только очищенное.
- При совпадении имени добавляется номер: `IMG (2).jpg`. Существующие файлы никогда не перезаписываются.
- Повтор у одного человека (тот же хэш среди не скрытых) не сохраняется. Это гарантирует и сама база (уникальный индекс), поэтому параллельные загрузки одного файла дают одну запись. Если такой файл у человека скрыт, загрузка возвращает его на место.
- Квота считает записи человека, включая скрытые. Файл, который уже лежит в облаке, в квоту всё равно входит полностью. Проверка идёт заранее по `Content-Length` и на лету, если длины нет. Предел одного файла `DVCLOUD_MAX_UPLOAD_BYTES` (по умолчанию 50 ГиБ).
- Файл принимается потоком во временный файл, память не растёт: на файле 600 МБ пик памяти сервера оставался около 150 МБ.
- Чужой и несуществующий файл неразличимы: ответ 404.
- Отдача с заголовками `X-Content-Type-Options: nosniff` и `Content-Security-Policy: default-src 'none'; sandbox`.
- Загрузка принимает только `application/octet-stream`: форма с чужого сайта так отправить не может, это защита от CSRF.

Альбомы, общий доступ и скачивание архивом описаны в docs/ALBUMS.md. Действия администратора над хранилищем в docs/ADMIN.md.

## Как работает загрузка на сайте

Сайт перед отправкой считает SHA-256 файла (до 128 МБ, в браузере, нужен https) и спрашивает у сервера `claim`. Если файл уже есть в облаке, он считается загруженным без передачи данных. Остальное уходит одним запросом (до 32 МБ) или по частям с докачкой, три файла одновременно. Папку можно выбрать кнопкой или перетащить в окно: подпапки раскрываются, не-фото и не-видео пропускаются. Перед пачкой больше пяти файлов сайт делает `estimate` и, если она не влезает в остаток квоты, предлагает «загрузить, сколько влезет» или «попросить больше места».

## Пока не сделано

- Дата снимка берётся со слов клиента (`X-File-Modified`), а не из EXIF. Чтение EXIF будет вместе с превью.
- Превью и постеры видео (этап превью).
- Автоочистка скрытых по сроку (срок открытый вопрос в DESIGN.md).
- Пересборка индекса сканированием диска.
