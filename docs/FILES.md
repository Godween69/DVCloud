# Файлы: хранение и API

Этап 1 из docs/DESIGN.md: загрузка, лента, скачивание, корзина, квота. Работает на публичном порту сервера (`/api`), вход по куке `dvcloud_sid`. Владелец всегда берётся из сессии, а не из запроса.

## Где что лежит

Всё внутри каталога данных `DVCLOUD_DATA_DIR` (в разработке `./data`, потом том на диске):

    library/<логин>/<год>/<месяц>/<файл>   оригиналы (год и месяц по дате снимка, UTC)
    trash/<логин>/<id>-<файл>              корзина
    tmp/                                   приём загрузки; чистится при старте сервера

Оригиналы обычные файлы: если сервер сломается, их можно открыть без него. База (таблица `files`) только индекс. Важно: `tmp` и `library` должны быть на одной файловой системе, иначе атомарное перемещение не сработает.

## Запросы

Все запросы с кукой входа. Ошибки приходят как JSON с полем `message`.

- `POST /api/files?name=IMG_1.jpg` тело запроса это сам файл, `Content-Type: application/octet-stream`. Необязательный заголовок `X-File-Modified` (ISO-дата или миллисекунды) задаёт дату снимка. Ответ 201 с описанием файла, либо 200 и `duplicate: true`, если такой файл (по SHA-256) уже есть.
- `GET /api/files?limit=100&before=<курсор>` лента, свежие сверху; `next` в ответе это курсор следующей страницы. С `trashed=1` показывает корзину.
- `GET /api/files/usage` занято, квота, число файлов.
- `GET /api/files/<id>` отдаёт оригинал; поддерживает Range (докачка, перемотка видео). С `?download=1` как вложение.
- `DELETE /api/files/<id>` в корзину.
- `POST /api/files/<id>/restore` вернуть из корзины (тело `{}` как JSON).
- `DELETE /api/files/<id>?permanent=1` окончательно, только из корзины.

## Правила

- Принимаются только фото и видео: jpg, jpeg, png, gif, webp, heic, heif, avif, tif, tiff, bmp, mp4, m4v, mov, avi, mkv, webm, 3gp. SVG и всё, что может нести скрипты, не принимается.
- Имя очищается: берётся последняя часть пути, убираются управляющие символы и `: * ? " < > |`, длина ограничивается. Путь на диске строится сервером, имя от клиента в нём только очищенное.
- При совпадении имени добавляется номер: `IMG (2).jpg`. Существующие файлы никогда не перезаписываются.
- Повтор у одного человека (тот же хэш среди не удалённых) не сохраняется. Это гарантирует и сама база (уникальный индекс), поэтому параллельные загрузки одного файла дают одну запись.
- Квота считает и корзину тоже. Проверка идёт заранее по `Content-Length` и на лету, если длины нет. Предел одного файла `DVCLOUD_MAX_UPLOAD_BYTES` (по умолчанию 50 ГиБ).
- Файл принимается потоком во временный файл, память не растёт: на файле 600 МБ пик памяти сервера оставался около 150 МБ.
- Чужой и несуществующий файл неразличимы: ответ 404.
- Отдача с заголовками `X-Content-Type-Options: nosniff` и `Content-Security-Policy: default-src 'none'; sandbox`.
- Загрузка принимает только `application/octet-stream`: форма с чужого сайта так отправить не может, это защита от CSRF.

Альбомы и скачивание архивом описаны в docs/ALBUMS.md.

## Пока не сделано

- Дата снимка берётся со слов клиента (`X-File-Modified`), а не из EXIF. Чтение EXIF будет вместе с превью.
- Превью и постеры видео (этап превью).
- Автоочистка корзины по сроку (срок открытый вопрос в DESIGN.md).
- Пересборка индекса сканированием диска.
