# Как развернуть свой DV Cloud

Для тех, кто скачал исходный код и хочет запустить облако у себя. Нужен только сервер с Docker. Чужих
сервисов в коде нет. Второй фактор входа (DV Auth) подключается по желанию, см. docs/TWOFACTOR.md.

## 1. Что понадобится

- Сервер с Linux и Docker (с плагином compose).
- Диск с достаточным местом под ваши файлы. Оригиналы лежат на нём обычными файлами.
- Для доступа из интернета: обратный прокси с HTTPS (nginx, Caddy и т.п.) и доменное имя.

## 2. Из чего состоит

Четыре контейнера (описание в docker-compose.example.yml):

- **db**: PostgreSQL. Хранит только указатель на файлы, людей и сессии. Файлы в нём не лежат.
- **server**: сервер облака. Публичный порт 3004 (вход и API) и внутренний 3006 (для админки). Оба
  доступны только внутри сети compose, наружу не публикуются.
- **admin**: локальная админка (люди, квоты, импорт). Порт 3005, опубликован только на 127.0.0.1.
- **web**: сайт. Отдаёт готовую сборку и пересылает запросы /api на сервер. Порт 80 внутри,
  в примере опубликован на 127.0.0.1:8080. Наружу выводите именно его, через ваш прокси с HTTPS.

## 3. Настройки

    cp dvcloud.env.example dvcloud.env
    chmod 600 dvcloud.env
    echo "POSTGRES_PASSWORD=$(openssl rand -hex 24)" > .env

В dvcloud.env важно:

- **DVCLOUD_INTERNAL_TOKEN**: не короче 32 символов (`openssl rand -hex 32`). Им сервер и админка
  узнают друг друга.
- **DVCLOUD_COOKIE_SECURE=true**: когда сайт открывается по https (в работе всегда).
- **DVCLOUD_ADMIN_COOKIE_SECURE**: true только если и админка открывается по https. Обычно админку
  открывают через ssh-туннель по http, тогда false.
- **DVCLOUD_TRUST_PROXY**: сколько прокси стоит перед сервером, считая контейнер web. Если перед
  облаком ваш прокси с HTTPS, ставьте 2 (web и ваш прокси). Напрямую, без своего прокси: 1.
  От этого числа зависит адрес, который видит сервер, и блокировка перебора пароля.
- **DVCLOUD_ADMIN_PASSWORD_HASH**: хеш пароля админки. Руками не пишется: `npm run admin:set-password`
  спросит пароль и запишет хеш в dvcloud.env сам.
- Адрес базы и каталог данных в примере compose заданы в самом файле compose.

Файлы dvcloud.env и .env содержат секреты: не добавляйте их в git (они в .gitignore).

## 4. Каталог файлов

    mkdir data
    sudo chown 1000:1000 data

Внутри контейнера сервер работает под пользователем node (номер 1000). Если каталог данных лежит на
отдельном диске, смонтируйте диск до запуска облака, иначе файлы окажутся на системном диске.

## 5. Запуск

    cp docker-compose.example.yml docker-compose.yml
    docker compose up -d --build

Миграции базы применяются при каждом старте сервера. Проверка:

    curl http://127.0.0.1:8080/api/health

Админка: http://127.0.0.1:3005 (с другого компьютера через `ssh -L 3005:127.0.0.1:3005 сервер`).
Через админку заводятся люди: регистрации в облаке нет.

## 6. Прокси с HTTPS

Выводите наружу только порт сайта (8080 в примере). Админку (3005) в интернет не выводите. Пример
для nginx:

    server {
        listen 443 ssl;
        server_name cloud.example.org;
        # ... ssl_certificate и ssl_certificate_key ...

        client_max_body_size 0;               # размер загрузки ограничивает облако, не прокси
        proxy_request_buffering off;          # файлы идут потоком, без временной копии на диске прокси
        proxy_read_timeout 3600s;
        proxy_send_timeout 3600s;

        location / {
            proxy_pass http://127.0.0.1:8080;
            proxy_set_header Host $host;
            proxy_set_header X-Forwarded-For $remote_addr;    # перезаписывать, не дописывать
            proxy_set_header X-Forwarded-Proto https;
        }
    }

Заголовок X-Forwarded-For надо **перезаписывать** на прокси (как в примере), иначе человек сможет
подставить чужой адрес.

## 7. Обновление

    git pull
    docker compose up -d --build

Данные (каталог data и база) при пересборке не затрагиваются.

## 8. Резервные копии

Копируйте каталог data и базу (`docker compose exec db pg_dump -U dvcloud dvcloud`). Копия должна
лежать на другом физическом диске, а лучше ещё и в другом месте. Оригиналы лежат обычными файлами,
поэтому достаточно любой программы резервного копирования файлов (restic, borg, rsync).

## 9. Если что-то не работает

- Сайт открывается, но вход не проходит и в браузере нет куки: при DVCLOUD_COOKIE_SECURE=true сайт
  должен открываться по https.
- Сервер не стартует и пишет про переменную: проверьте dvcloud.env (токен не короче 32 символов).
- Файл не загружается и обрывается: проверьте client_max_body_size и таймауты на вашем прокси.
- Все входы выглядят как один адрес: неверное число в DVCLOUD_TRUST_PROXY или прокси дописывает
  X-Forwarded-For, а не перезаписывает.
