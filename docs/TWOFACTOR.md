# Второй фактор входа

DV Cloud может требовать второй фактор после пароля. Для этого он подключается к отдельному
сервису [DV Auth](https://github.com/Godween69/DVAuth) (открытый исходный код, AGPL-3.0).
Облако само не хранит ни секретов, ни кодов: оно проверяет пароль, а второй шаг делает DV Auth.

Если DV Auth не подключён, облако работает как раньше, вход идёт по паролю. Подключение
необязательное, и так задумано: тот, кто развернул облако из публичного репозитория, сам решает,
нужен ли ему второй фактор.

## Два способа

**Подтверждение в DVChat** (основной). После пароля сайт показывает QR-код и число. Человек
наводит на код сканер в приложении [DVChat](https://github.com/Godween69/DVChat), видит, кто и
откуда входит, и вводит число с экрана. Вход подтверждён. Так же устроен вход в WhatsApp Web,
но на своём сервере. Чат проверяет личность через Matrix OpenID, пароль и токены чата в облако и
DV Auth не попадают. Подробности: docs/CHAT.md в репозитории DV Auth.

**Коды из приложения-аутентификатора** (запасной). Google Authenticator, Aegis, 2FAS и любые
другие с поддержкой TOTP. Работает без чата и без интернета на телефоне.

К обоим способам выдаются **десять запасных кодов**: каждый работает один раз и нужен, если телефон
потерян или чат недоступен. Их показывают один раз при первой настройке, сохраните сразу.

## Как человек пользуется

1. После входа в облако открыть «Безопасность» (значок щита в шапке).
2. Привязать DVChat: ввести пароль, показать QR-код, отсканировать его в DVChat, ввести число.
3. По желанию включить коды из приложения: ввести пароль, отсканировать QR-код в
   аутентификаторе, ввести первый код.
4. Сохранить запасные коды.

При следующем входе после пароля появится второй шаг: QR-код с числом или поле для кода.
«Открыть в DVChat» на телефоне открывает тот же запрос прямо в приложении.

Опасные действия (отвязать чат, выключить коды, выпустить новые запасные коды) требуют пароль,
а когда включены коды из приложения, ещё и код.

## Как подключить облако к DV Auth

Развернуть DV Auth по его документации (docs/DEPLOY.md в репозитории DV Auth), добавить облако
в список приложений (`DVAUTH_CLIENTS`: id, название и секрет не короче 32 символов), затем в
окружении облака задать:

    DVCLOUD_AUTH_URL=http://127.0.0.1:3011      # внутренний порт DV Auth, наружу не публиковать
    DVCLOUD_AUTH_SECRET=<тот же секрет>         # не короче 32 символов, в git не попадает

Оба значения задаются вместе. Перезапустите сервер облака. В «Безопасности» появятся настройки.

## Правила безопасности

- **Нет DV Auth: нет входа тем, кто включил второй фактор.** Если DV Auth настроен, но не отвечает
  или не принимает секрет, вход закрыт и показывается «Сервис второго фактора недоступен». Облако
  не пропускает человека «на всякий случай»: неизвестно, включён ли у него второй фактор.
  Аварийный выход для администратора: убрать `DVCLOUD_AUTH_URL` и `DVCLOUD_AUTH_SECRET` и
  перезапустить сервер (второй фактор временно отключится у всех, делайте это осознанно).
- **Идентификатор человека в DV Auth** это его номер в облаке, а не логин.
- **Сессия открывается только после второго шага**, а для человека, которого отключили между
  шагами, не открывается совсем.
- **Сброс** (администратор потерявшему телефон и запасные коды): в админке кнопка «Сбросить 2FA».
  Она снимает все факторы в DV Auth и закрывает сессии человека. После входа по паролю он
  настраивает второй фактор заново.
- **Блокировка перебора** считается и в облаке (пароль), и в DV Auth (коды).

## Проверка

- Сервер: `npm run test:db --workspace @dvcloud/server` проверяет, как облако пользуется DV Auth
  (заглушка DV Auth, настоящий Postgres).
- Сам DV Auth проверен собственными тестами в его репозитории.
- Вся цепочка (сайт, облако, настоящий DV Auth, имитация приложения чата) прогнана в настоящем
  браузере: привязка, вход, чужой аккаунт, запасные коды, отвязка, телефон.
