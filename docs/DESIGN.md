# DVCloud: проект семейного облака для фото

Документ описывает цели, архитектуру и защиту. Секретов, адресов серверов и ключей в нём нет.

Состояние: черновик от 02.11.2026, кода ещё нет. Решения помечены:
**(решено)** принято владельцем проекта, **(предложено)** предложено и подтверждается при реализации.

## 1. Цель и границы

- Своё домашнее облако для фото и видео семьи на своём сервере. (решено)
- Минимум четыре человека, у каждого своё пространство. (решено)
- Веб-галерея и приложение для Android с автоматической выгрузкой. (решено)
- Загрузка не только с телефонов: целую папку с компьютера или флешки загружает администратор. (решено)
- Только фото и видео. Файлы общего назначения, если понадобятся, отдельным этапом. (предложено)
- Не делаем: распознавание лиц, умный поиск, соцсеть, публичные галереи, внешние сервисы и счётчики. (предложено)

## 2. Принципы

1. **Оригиналы это обычные файлы** в понятных папках. База данных только индекс: её можно пересобрать сканированием диска. Если приложение сломается, фото остаются целы и открываются без него. (предложено)
2. **Ничего не удаляется насовсем:** удалённое уходит в корзину, стирается окончательно только явным действием или по сроку. (предложено)
3. **Минимум служб:** сервер и база Postgres. Без Redis, очередей и внешних сервисов. (предложено)
4. **Диск может спать.** Оригиналы лежат на медленном диске, который засыпает при простое. Превью и база на быстром диске, поэтому лента листается, не будя оригиналы. Клиент умеет ждать пробуждения. (решено)
5. **Файл считается враждебным,** пока не доказано обратное (раздел 8). (предложено)

## 3. Архитектура

    браузер или приложение  ->  HTTPS-прокси  ->  сервер (NestJS и сайт React)  ->  Postgres
                                                              |
                                                     файлы на диске
    локальная админка  ->  сервер (внутренний адрес, наружу не публикуется)

- Клиенты ходят только к серверу: он один работает с файлами и базой.
- Админка отдельное приложение: слушает только локальный адрес и не входит в сайт. (решено)
- Сервер и сайт собираются в один образ Docker, контейнер без root. (предложено)
- Клиент хранит список адресов сервера и выбирает доступный: если один недоступен из текущей сети, пробует следующий. (решено)

## 4. Каталоги данных

    library/<логин>/<год>/<месяц>/<файл>   оригиналы
    inbox/<логин>/                          папка приёма для импорта
    trash/<логин>/                          корзина
    cache/<логин>/                          превью и сжатые копии видео (быстрый диск)

- Папка человека называется по логину, который после создания не меняется. (предложено)
- Имя файла сохраняется, при совпадении добавляется суффикс. Хэш SHA-256 каждого файла хранится в базе: по нему находятся повторы. (предложено)
- Дата в пути берётся из метаданных снимка (EXIF), если их нет, то из даты файла. (предложено)
- Каталоги данных живут вне репозитория и образа, подключаются томами.

## 5. Люди и права

- Регистрации нет. Людей создаёт администратор и выдаёт им вход. (решено)
- Каждый видит только свою библиотеку. Общие альбомы между людьми возможны позже (раздел 9).
- Квота на человека. (предложено)
- Админка показывает людей, объём и состояние, но не показывает чужие фото. (предложено)
- Честная оговорка: файлы лежат на диске в открытом виде, поэтому тот, у кого есть доступ к серверу, технически может их прочитать. Шифрование на диске пока не делается (раздел 9).

## 6. Загрузка

- **С телефона (Android):** автоматическая выгрузка новых фото и видео в фоне, по желанию только по Wi-Fi. Приложение помнит, что уже выгружено, повторы отсекаются по хэшу.
- **Через сайт:** выбор или перетаскивание файлов, для небольших объёмов.
- **Импорт из папки (админка):** файлы кладутся в папку приёма на диске сервера (с компьютера по сети или с флешки), затем в админке выбираются человек и папка.
  1. Пробный просмотр: сколько файлов и гигабайт, что новое, что уже есть, что не фото и не видео.
  2. Импорт в фоне с прогрессом и журналом, его можно остановить и продолжить.
  3. Режим «скопировать» (по умолчанию) или «переместить».
  4. Нагрузка ограничена: один-два потока, пониженный приоритет.
  5. Читать можно только внутри папки приёма: выход наружу через «..» и символические ссылки запрещён.
- Большие файлы принимаются потоком, без буферизации целиком в памяти и без временных копий на системном диске.

## 7. Превью и просмотр

- Для ленты строятся маленькие превью, они лежат в cache. Оригинал отдаётся по запросу.
- Видео: постер и сжатая копия для просмотра, оригинал сохраняется.
- Канал домашнего сервера наружу ограничен, поэтому вне дома лента идёт на превью, а оригиналы по запросу.
- Если ответ задерживается из-за пробуждения диска, клиент показывает «диск просыпается» и повторяет запрос.

## 8. Угрозы и защита

- Вредоносный файл: подложенные метаданные, огромные картинки («бомба распаковки»). Обработка с ограничением размера, времени и памяти.
- Выход за пределы папки: проверка путей при импорте и скачивании.
- Подбор пароля, кража сессии: ограничение попыток входа, кука HttpOnly, Secure, SameSite, срок простоя.
- Чужие файлы: проверка владельца на каждый запрос.
- Взлом сервера: контейнер без root, файловая система только для чтения, где возможно, админка только на локальном адресе.
- Потеря данных: корзина, раздельные оригиналы и превью, и главное: **резервная копия на другом носителе обязательна**, RAID её не заменяет.
- Цепочка поставки: проверка лицензий и уязвимостей зависимостей.

## 9. Открытые вопросы

- Шифрование файлов на диске: усложняет восстановление без приложения.
- Общие семейные альбомы между людьми.
- Срок хранения корзины.
- Форматы: HEIC, RAW, живые фото.
- Файлы общего назначения (документы).

## 10. Этапы

- Этап 0: репозиторий и документация.
- Этап 1: сервер: вход, пользователи, хранение файлов, превью; тесты на настоящем Postgres.
- Этап 2: веб и локальная админка.
- Этап 3: импорт из папки.
- Этап 4: приложение для Android с автовыгрузкой.
