# Яндекс Диск

Раздел «Яндекс Диск» нужен тем, у кого фото и видео лежат в безлимите Яндекс Диска (папка «Фотокамера» и автозагрузка с телефона). Каждый человек подключает свой Диск в своём аккаунте DV Cloud и забирает файлы в свою библиотеку. Это односторонний перенос: DV Cloud только читает с Яндекса, ничего там не меняет и не удаляет, а удаление на Яндексе ничего не удаляет у вас.

Важно: это неофициальный способ. У безлимита нет публичного программного интерфейса, поэтому DV Cloud работает так же, как веб-страница Диска в браузере. Яндекс может изменить страницу, и тогда подключение придётся чинить. Используйте его только со своим аккаунтом и для личных файлов.

## Как это выглядит для человека

1. Во вкладке «Яндекс Диск» нажмите «Показать QR-код».
2. Откройте приложение Яндекс на телефоне, где вы уже вошли, наведите камеру на QR и подтвердите вход. Пароль Яндекса в DV Cloud не вводится никогда.
3. Нажмите «Прочитать список». DV Cloud прочитает названия, размеры и контрольные суммы файлов безлимита (на десять тысяч файлов уходит около 20 секунд). Сами файлы пока не скачиваются.
4. Отметьте годы, которые нужны (если ничего не отмечено, забираются все), и нажмите «Забрать в DV Cloud». Файлы скачиваются по одному в фоне, можно закрыть страницу. Ход, скорость и оставшееся время видны на вкладке.
5. Забранные файлы попадают в вашу библиотеку и, если галочка стоит, в альбом «Яндекс Диск».

Дата снимка берётся из даты файла на Яндексе, поэтому файлы с именами вроде `1970-06-08 12-50-41.JPG` встают в ленту на свои настоящие даты, а не в 1970 год.

## Что происходит с файлами

- Одинаковое содержимое хранится один раз. Если у двух людей на сервере есть один и тот же файл, на диске лежит одна копия, а у каждого человека своя ссылка на неё. Для файла, который уже есть на сервере (совпала контрольная сумма с Яндекса), даже скачивание не нужно: ссылка создаётся сразу.
- Не фото и не видео помечаются «пропущен» и не забираются.
- Если не хватает места по квоте, забор ставится на паузу с понятной причиной. Файлы, которые уже есть на сервере, места не занимают.
- Если Яндекс не отдаёт файл (ограничение частоты, пауза сервера), файл ждёт и пробуется снова примерно каждые полчаса, до восьми попыток. Если файла на Яндексе больше нет, он помечается «не получилось».
- Если Яндекс закрыл сессию, вкладка предложит подключиться заново. Список и очередь сохраняются.
- Кнопка «Отключить» удаляет сохранённый вход. Забранные файлы остаются.

Альбомы, общие альбомы и доступ членов семьи друг к другу работают так же, как для любых других файлов (см. [ALBUMS.md](ALBUMS.md)).

## Безопасность

- Сохранённый вход (куки Яндекса) хранится в базе в зашифрованном виде (AES-256-GCM). Ключ берётся из `DVCLOUD_SECRETS_KEY` и в базе не хранится. Потеряете ключ — придётся подключить Диск заново.
- Куки отправляются только на адреса Яндекса и нигде не пишутся в журналы. Перенаправления проверяются вручную, чтобы куки не ушли на чужой адрес.
- Человек видит и использует только свой Диск. Администратор в своей панели видит лишь числа: сколько Дисков подключено, сколько файлов в списках и сколько забрано. Содержимое входов ему недоступно.
- Вход по QR выполняет отдельный маленький сервис (помощник входа). Он открывает настоящую страницу входа Яндекса в браузере без интерфейса, показывает QR, дожидается подтверждения на телефоне и передаёт серверу куки. Помощник защищён общим секретом (`DVCLOUD_YANDEX_LOGIN_TOKEN`), не публикуется наружу и ничего не хранит после завершения входа.

## Как включить

Раздел выключен, пока не заданы три значения в `dvcloud.env`. Задаются они вместе:

    DVCLOUD_SECRETS_KEY=<случайная строка не короче 32 символов>
    DVCLOUD_YANDEX_LOGIN_TOKEN=<случайная строка не короче 32 символов>
    DVCLOUD_YANDEX_LOGIN_URL=http://login:8099

Случайную строку можно получить командой `openssl rand -hex 32`. Не публикуйте эти значения.

Помощник входа запускается отдельным контейнером из того же `Dockerfile` (цель `login`). В `docker-compose.example.yml` он описан сервисом `login` с профилем `yandex`:

    docker compose --profile yandex up -d

Контейнеру не нужны порты наружу, только доступ с сервера DV Cloud по внутренней сети. Образ включает Chromium из пакетов Alpine, поэтому он заметно больше остальных (порядка нескольких сотен мегабайт). Ограничения в примере (без прав, только чтение, память до 1 ГБ) можно оставить как есть.

Дополнительные настройки (необязательно): `DVCLOUD_YANDEX_BASE` (адрес веб-версии Диска, по умолчанию `https://disk.yandex.ru`), `DVCLOUD_YANDEX_RETRY_MIN` (через сколько минут повторять, по умолчанию 30), `DVCLOUD_YANDEX_TICK_MS` (период проверки очереди, по умолчанию 5000).

## Устройство

- Сервер: модуль `apps/server/src/yandex`. `disk.client.ts` читает список (`/photounlim`) и скачивает файлы, `crypto.ts` шифрует вход, `login.client.ts` разговаривает с помощником, `yandex.service.ts` ведёт очередь и фоновый забор, `yandex.controller.ts` отдаёт интерфейс `/api/yandex`.
- Таблицы: `yandex_accounts` (по одной на человека) и `yandex_items` (файлы из списка и их состояния: new, queued, done, waiting, failed, skipped), миграция `0011_yandex.sql`.
- Помощник входа: `apps/login`.
- Веб: вкладка `YandexView`, помощники в `apps/web/src/lib/yandex.ts`.
- Тесты: сервер проверяется против поддельного Яндекса и поддельного помощника (`yandex.integration.ts`), помощник тестируется отдельно (`npm run test:login`).
